1. Démarrage rapide

Pour gérer le site au quotidien, tu n’as normalement pas besoin de modifier le code. Commence par le centre de gestion.

Ouvre « Centre de gestion »Connecte-toi avec ton accès administrateur. Le tableau de bord regroupe les cadeaux, réservations, participations, suggestions et réglages.
Modifie ce qui doit l’êtreUtilise les éditeurs prévus dans l’interface plutôt que de toucher directement aux fichiers lorsque c’est possible.
Vérifie le site publicAprès une modification, ouvre la liste et teste sur téléphone et ordinateur.
Publie seulement après vérificationLes changements de fichiers GitHub sont déployés par GitHub Pages.
Règle simple : administration courante = admin.html ; modification technique = GitHub ; données persistantes = Supabase.

3. Gérer les cadeaux

Une fiche cadeau contient notamment un titre, une description, une catégorie et un prix indicatif. Certaines fiches peuvent aussi avoir un objectif de financement et des options de réservation.

Ajouter ou modifier

  1. Ouvre la section des cadeaux dans l’administration.
  2. Renseigne les informations clairement.
  3. Active uniquement les options nécessaires : réservation ou participations.
  4. Enregistre.
  5. Contrôle l’affichage de la carte sur la page publique.

Financement

Si un objectif est défini, le site calcule l’avancement, le montant restant et le nombre de participations. Évite de modifier manuellement une donnée calculée si l’interface prévoit déjà la gestion des contributions.

4. Réservations et participations

Réservations

Une réservation sert à signaler qu’un cadeau est pris. Le site affiche le nom associé et propose une action de dé-réservation lorsque celle-ci est autorisée.

Participations financières

Les contributions sont stockées côté Supabase. L’administration permet de suivre les montants et les messages. Une contribution peut être réduite ou retirée selon les fonctions disponibles.

Attention : ne supprime pas directement des lignes Supabase « pour tester ». Utilise les actions prévues par le site afin de conserver la cohérence des montants.

5. Gérer HYDRA

HYDRA est l’espace interactif spécial. Ses fichiers principaux sont dans hydra/, avec des fichiers complémentaires à la racine.

hydra/interactive.htmlInterface interactive HYDRA.
hydra/audio.jsSons et musique de l’interface HYDRA.
hydra/music/Fichiers audio locaux de la playlist.
hydra/manifest.jsonConfiguration de l’application HYDRA.
hydra/sw.jsService worker de l’espace HYDRA.
hydra/vm-*.jsModules liés à la machine virtuelle et aux effets.

Modifier une expérience

  1. Identifie le fichier correspondant à la fonction.
  2. Fais une petite modification à la fois.
  3. Teste navigation, boutons et affichage mobile.
  4. Vérifie la console du navigateur si quelque chose ne répond plus.
  5. Publie avec un commit clair.

6. Musique et sons

La playlist instrumentale HYDRA est locale. Les fichiers sont dans hydra/music/ et sont référencés depuis hydra-audio.js.

La playlist actuelle contient NEON PULSE, MIDNIGHT DRIVE et DIGITAL RUSH. Le lecteur gère le volume, l’activation des sons et le passage au morceau suivant.

Ajouter un morceau

  1. Ajoute le fichier audio dans hydra/music/.
  2. Ajoute son chemin et son nom dans la liste BGM de hydra-audio.js.
  3. Vérifie que le fichier est bien accessible depuis les pages HYDRA.
  4. Teste après publication.
Droits : utilise uniquement des musiques que tu as le droit d’héberger et de diffuser. « Sans paroles » ne signifie pas automatiquement « libre de droits ».

7. GitHub et publication

Le dépôt contient le code source et GitHub Pages publie la version du site.

Organisation utile

index.html → site principal admin.html → administration communaute.html → communauté confidentialite.html → confidentialité hydra/ → modules HYDRA hydra/music/ → musiques locales supabase/ → fonctions/configuration Supabase src-tauri/ → application native

Pour une modification technique

  1. Modifie le fichier concerné.
  2. Fais un commit décrivant précisément le changement.
  3. Attends le déploiement GitHub Pages.
  4. Recharge le site avec un rafraîchissement forcé si nécessaire.
Bon réflexe : un commit = une modification logique. Cela rend les retours en arrière beaucoup plus simples.

8. Supabase : les données

Supabase sert de backend pour les données persistantes du site : réservations, contributions, suggestions, messages et autres fonctions selon la configuration actuelle.

Quand utiliser Supabase ?

Utilise-le lorsqu’une donnée doit être partagée entre plusieurs visiteurs et rester disponible après fermeture du navigateur. Les données temporaires d’interface, elles, peuvent rester côté navigateur.

Avant une modification SQL

  1. Comprends exactement la table ou fonction concernée.
  2. Vérifie les politiques RLS.
  3. Fais une modification ciblée.
  4. Teste lecture et écriture avec le même niveau d’accès que le site.

9. Sécurité

  • Ne mets jamais une clé secrète Supabase ou un mot de passe administrateur dans un fichier public.
  • Les clés publiques destinées au navigateur ne remplacent pas les politiques RLS.
  • Valide les données côté backend, pas uniquement avec JavaScript.
  • Évite de transmettre des codes d’accès dans des URL partageables.
  • Pour une modification sensible, teste d’abord avec un compte de test.
À retenir : tout ce qui est envoyé au navigateur peut potentiellement être inspecté par un visiteur. Les vrais secrets doivent rester côté serveur.

10. Dépannage

Le changement n’apparaît pasAttends le déploiement, puis fais un rechargement forcé. Vérifie aussi que le commit est bien sur main.
HYDRA ne joue pas la musiqueLe navigateur peut bloquer l’audio automatique. Fais une première interaction avec la page, puis vérifie le bouton audio et le volume.
Une image ne s’affiche pasVérifie son chemin, son extension et son accessibilité. Le site masque les images qui échouent au chargement.
Une donnée ne se sauvegarde pasVérifie la réponse Supabase, la fonction RPC concernée et les politiques RLS.
La visite guidée cible malVérifie que le sélecteur cible un élément réel du DOM et que l’élément existe dans la vue active.
Tout semble cassé après une modificationRegarde la console navigateur et reviens au dernier commit fonctionnel plutôt que d’empiler plusieurs corrections.
